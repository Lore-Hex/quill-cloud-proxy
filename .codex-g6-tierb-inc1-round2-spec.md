## Finding 1 (BLOCKER) — nonce-confusion relay on the GCP flat eat_nonce list

The GCP token puts the server-derived exporter AND the caller-supplied `?nonce`
as indistinguishable hex entries in `eat_nonce`, and verifiers match by
membership. Attack: an operator proxy P (holds the shared key, terminates the
client C's TLS) computes C's session exporter `X_C`, opens its own session to
the real enclave E, and requests `/attestation?nonce=hex(X_C)`. E returns a
genuine token whose `eat_nonce` contains `hex(X_C)` in the CALLER slot (plus
E's real exporter `X_P` in the exporter slot). A verifier that only checks
`hex(exporter) in nonces` passes → relay succeeds.

**Closure (proven, CSP-charset-agnostic): the mandatory-independent-freshness
+ single-caller-slot argument.** The enclave honors exactly ONE caller nonce
(`url.Query().Get` returns the first). So a relay can inject AT MOST ONE value
into `eat_nonce`. If the verifier REQUIRES BOTH (a) its own fresh random nonce
`R` present AND (b) `hex(exporter)` present AND (c) `R != hex(exporter)`, the
single caller slot can carry at most one of {`R`, `X_C`}; the other must come
from a server-derived slot, but the exporter slot for a relay is `X_P != X_C`
and no slot is `R` unless P spent its one slot on `R` (then `X_C` is absent).
P cannot satisfy both → relay fails. This holds with no assumption about CSP
nonce ordering or charset — only the single-caller-nonce fact.

Make it a PROTOCOL REQUIREMENT, not client discretion:

### 1a. Enclave — guarantee the single-caller-nonce premise
- In `parseRequestTarget` (`cmd/enclave/http_io.go`), if the query string
  contains MORE THAN ONE `nonce` parameter, reject the request (400
  "multiple nonce parameters"). Today `.Get` silently takes the first; make
  the premise explicit and enforced so a future change can't quietly allow
  two caller-controlled slots. Add a why-comment citing the single-slot
  closure. Add a unit test: two `?nonce=` params → 400.
- Keep the exporter appended to `Nonces` BEFORE the caller nonce (unchanged).
  Keep it pure hex (CSP-safe). Do NOT rely on positional/charset tricks.

### 1b. Reference verifier — make freshness mandatory + fix --binding-stress
`tools/verify-attestation.py`:
- The main (`--samples`) GCP check already sends `?nonce=<random>` and checks
  the exporter. REQUIRE all three now (fail closed if any missing): a freshly
  generated random `nonce_hex` (>=16 bytes, `secrets.token_hex`), present in
  `eat_nonce`; `hex(exporter)` present in `eat_nonce`; and
  `nonce_hex != hex(exporter)`. Restructure so the freshness check is NOT
  optional — if `exporter` is present but the random nonce was not sent/echoed,
  FAIL (the exporter-alone check is insufficient per Finding 1).
- `--binding-stress` (line ~500-523): it sends `nonce_hex` but the result
  ignores it. Add `nonce_bound = nonce_hex in nonces` to the result and make
  the pass verdict require `cert_bound AND exporter_bound AND nonce_bound`
  (codex P2). A relay that injects `X_C` as the caller nonce then lacks the
  random `nonce_hex` and is correctly flagged not-bound.
- Add a module-level doc block: "SECURITY: the exporter check ALONE is
  insufficient. A relay can launder the client's own exporter through the
  caller-nonce channel. Every verifier MUST also send a fresh random nonce and
  require it present; the enclave honors only one caller nonce, so a relay
  cannot supply both the random nonce and the client exporter." SDK
  implementers will mirror this.

## Finding 2 (BLOCKER) — verifier crashes on Python >= 3.12 (removed ssl.match_hostname)

with proper wildcard handling (`*.example.com` matches one label). Raise a
clear error on mismatch. Add a small unit test (a self-signed cert with a SAN,
