## Fix 1 (should-fix) — verifier: clean [FAIL] on IDNA-invalid SAN, not a traceback

`tools/verify-attestation.py`: the attacker controls the presented cert. A SAN
DNS pattern with an empty label (`.example.com`) or a >63-char label raises an
uncaught `UnicodeEncodeError` from `label.encode("idna")` in
`_normalize_dns_name` / `_dnsname_matches`, invoked by
`assert_cert_matches_hostname` OUTSIDE any try/except. It already fails closed
(non-zero exit) but dies with a raw traceback instead of the intended
`[FAIL] TLS certificate hostname mismatch`, which a stdout-grepping health gate
(the DNS reconciler) could mishandle. Fix: treat an un-encodable SAN pattern as
NON-MATCHING (catch the encode error inside the per-pattern matcher and return
False for that pattern) so an invalid SAN cleanly yields the hostname-mismatch
`[FAIL]`. Add an offline unit test in `tools/test_verify_attestation.py`: a cert
with a SAN like `.example.com` (and one with a 64-char label) → clean mismatch,
no exception. (This test needs the cryptography backend; see Fix 4.)

## Fix 2 (nit → do it) — structural fail-closed on empty exporter

`enclave-go/cmd/enclave/main.go` `/attestation` handler currently guards
`if err != nil && leafDER != nil`. Harden to also fail closed when the exporter
is empty on a TLS connection:
```go
if leafDER != nil && (err != nil || len(exporter) == 0) {
    writeError(conn, 503, "attestation: exporter channel binding unavailable")
    return
}
```
So a `(nil, nil)` return from `SelectedExporter` can never produce an unbound
(relayable) token — the invariant is enforced structurally, not just by the
TLS-1.3 floor. Update/extend the fail-closed test to cover the empty-exporter
case (a fake conn/asserter returning `(nil, nil)`).

## Fix 3 (nit) — reject oversized caller nonce up front with 400

`enclave-go/cmd/enclave/http_io.go` `parseRequestTarget`: the caller nonce cap
is `maxAttestationNonceBytes = 64` raw bytes, which hex-encodes to up to 128
chars — exceeding Confidential Space's 74-byte-per-nonce limit, so an oversized
nonce currently yields a downstream 500 from the launcher instead of a clean
client error. Lower the cap so the HEX string stays ≤ 74 bytes: set
`maxAttestationNonceBytes = 37` (37 bytes → 74 hex chars). Requests with a
larger nonce already return 400 via the existing length check — keep that path,
just tighten the constant, and update its comment to explain the CSP 74-byte
nonce-string limit. (The bundled verifier sends ≤32-byte nonces, so it is
unaffected; leafFP/deviceHash/exporter are 32-byte → 64 hex, within limit.)
Add/adjust a unit test: a 38-byte nonce → 400.

## Fix 4 (nit) — don't let hostname tests silently pass by skipping

`tools/test_verify_attestation.py`: the `HostnameVerificationTests` skip when the
`cryptography` backend is unavailable. The verifier module itself imports
`cryptography.x509`, so any environment that can run the tool has the backend —
the skip only hides local dev gaps. Ensure the tool declares `cryptography` in
its inline script dependencies / requirements so CI installs it, and make the
hostname tests FAIL (not skip) when an env var `TR_REQUIRE_CRYPTO=1` is set
(CI sets it) while still skipping for convenience locally. Keep the offline
anti-relay nonce tests as-is (they need no backend).
