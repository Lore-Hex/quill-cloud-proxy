# Task: G6 Tier B inc1 round 6 — fix the pyOpenSSL non-blocking TLS I/O bug (verifier can't handshake live)

Fix round on branch `g6-tierb-exporter-binding` (build on rounds 1-5; revert
nothing). The enclave deploy fails at `Reconcile enclave DNS` because the
reference verifier CRASHES on a real network handshake:

```
File "tools/verify-attestation.py", line 440, in fetch_attestation_same_tls_socket
    conn.do_handshake()
  ...
OpenSSL.SSL.WantReadError
```

Root cause: `socket.create_connection((host,port), timeout=10)` puts the socket
in TIMEOUT mode (non-blocking under the hood). pyOpenSSL's `SSL.Connection` over
a timeout-mode socket raises `WantReadError` / `WantWriteError` from
`do_handshake()`, `send()`, `recv()` whenever the operation can't complete in a
single syscall (normal for a multi-round-trip TLS handshake). The code never
retries via `select`, so it crashes on EVERY live connection. Offline tests
never caught this — the live pyOpenSSL path was never exercised against a real
server. This is client-side; it fails against old AND new enclaves alike.

Do NOT commit. Do not touch `.codex-*` files.

## Fix — retry pyOpenSSL socket I/O on WantRead/WantWrite with a deadline

Add a small helper and use it for ALL pyOpenSSL blocking-BIO operations
(handshake, send, recv) in the live paths, respecting an overall timeout:

```python
def _ssl_call(sock, op, *, timeout, what):
    """Run a pyOpenSSL socket-BIO op (handshake/recv/send) that may raise
    WantRead/WantWrite in timeout mode, retrying via select until it completes
    or the deadline passes. pyOpenSSL over a timeout-mode socket does not block;
    it signals readiness this way (this is the standard socket-BIO pattern)."""
    deadline = <monotonic-now> + timeout
    while True:
        try:
            return op()
        except SSL.WantReadError:
            remaining = deadline - <monotonic-now>
            if remaining <= 0 or not select.select([sock], [], [], remaining)[0]:
                raise TimeoutError(f"{what}: TLS read timeout")
        except SSL.WantWriteError:
            remaining = deadline - <monotonic-now>
            if remaining <= 0 or not select.select([], [sock], [], remaining)[1]:
                raise TimeoutError(f"{what}: TLS write timeout")
```
(Use `time.monotonic()` — NOT `Date.now`. Import `select`, `time`.)

Apply it in BOTH live functions:
- `fetch_attestation_same_tls_socket` (line ~435): keep the socket; wrap
  `conn.do_handshake()` → `_ssl_call(raw, conn.do_handshake, timeout=..., what="handshake")`.
  Route `conn.sendall(...)` and the recv in `_recv_or_fail`/`_read_http_response`
  through the helper too (they hit the same WantRead/WantWrite). Simplest:
  give `_recv_or_fail` the raw socket + timeout and wrap `conn.recv(N)`; wrap
  sends similarly. Also wrap the follow-up (pin) request's send/recv.
- `_probe_binding` / the `--binding-stress` path (socket at line ~506): same
  wrapping so it doesn't crash the same way.
Choose a sensible per-op timeout (e.g. 15s) and thread it so the whole
same-socket sequence stays within the reconciler's 45s subprocess budget.

Alternative you may use IF cleaner and correct: set the socket BLOCKING for TLS
ops (`raw.setblocking(True)` after connect) and enforce the deadline with a
socket timeout via `raw.settimeout(...)` — BUT note settimeout re-enters
timeout mode and reintroduces WantRead, so blocking + an outer watchdog is the
only pure-blocking option. The select-retry helper above is preferred because
it keeps a real deadline without hanging.
