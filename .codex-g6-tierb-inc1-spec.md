# Task: G6 Tier B, Increment 1 — TLS-exporter channel binding in the attestation token (enclave + reference verifier)

Closes the DevProof G6 relay gap: today the attestation binds the TLS **cert**
(`SHA256(leafDER)`), and the cert+key are shared/exportable via GCS, so an
operator proxy holding the key relays a genuine token and MITMs plaintext. Fix:
bind the token to the live TLS **session** via RFC 9266 `tls-exporter` keying
material, **derived server-side from the enclave's own `*tls.Conn`** — a value
the caller cannot supply or forge. A MITM proxy terminates a *different* TLS
session (different master secret) and can neither obtain a token bound to the
client's exporter nor mint one itself.

This increment is enclave-side + the reference verifier only. It is
**additive and backward-compatible**: old verifiers ignore the new nonce and
keep working; new verifiers gain the binding check. No deploy (Joseph's call).

`.codex-*` files. Enclave code is `enclave-go/`.

## Design (implement exactly)

Standard binding: RFC 9266 `tls-exporter` — exporter label
`"EXPORTER-Channel-Binding"`, empty context, 32 bytes. Define one shared const
so enclave + verifier can't drift.

### 1. `enclave-go/internal/enclavetls/cert.go` — server-side exporter accessor

Mirror the existing `SelectedLeafDER(net.Conn) []byte` pattern exactly.

- Add exported const `ExporterLabel = "EXPORTER-Channel-Binding"` and
  `ExporterLength = 32`.
- Add `func SelectedExporter(conn net.Conn) ([]byte, error)`:
  - Type-assert `conn` to an interface exposing
    `ConnectionState() tls.ConnectionState` (both `*tls.Conn` and
    `*trackedTLSConn` satisfy it via the embedded `*tls.Conn`). If it doesn't
    satisfy, return `(nil, error)` "not a TLS connection".
  - `state := c.ConnectionState()`. If `!state.HandshakeComplete` →
    error. If `state.Version < tls.VersionTLS13` → error
    "exporter channel binding requires TLS 1.3" (soundness: TLS 1.2 exporters
    are EMS-dependent; the attested path must be 1.3).
  - Return `state.ExportKeyingMaterial(ExporterLabel, nil, ExporterLength)`.
  Dense why-comment: this is derived from the ENCLAVE's live session; a relay
  proxy's client-facing session has a different master secret, so it cannot
  present a token bound to this value (the G6 closure).

### 2. `enclave-go/cmd/enclave/http_io.go` — forward through the stats wrapper

`responseStatsConn` already forwards `SelectedLeafDER` →
`enclavetls.SelectedLeafDER(c.Conn)`. Add the twin:
`func (c *responseStatsConn) SelectedExporter() ([]byte, error) { return enclavetls.SelectedExporter(c.Conn) }`
and have `enclavetls.SelectedExporter` at the call site resolve it the same way
`SelectedLeafDER` does — i.e., make `SelectedExporter(net.Conn)` first try a
`{ SelectedExporter() ([]byte, error) }` asserter (satisfied by
`responseStatsConn`), else fall back to the `ConnectionState()` asserter. Keep
symmetry with the leaf accessor so the pattern is obvious.

### 3. `enclave-go/internal/attestation/*.go` — bind it into the token

Change the shared signature in BOTH build variants (they must both compile):
`func Get(leafDER, deviceBlob, nonce, channelBinding []byte) ([]byte, error)`.

- **GCP variant (`attestation_gcp.go`, the live/audited path):** append
  `hex(channelBinding)` to the `Nonces` list as a distinct entry when
  `len(channelBinding) > 0`, placed AFTER leafFP+deviceHash and BEFORE the
  optional caller nonce. (Verifiers match by membership, not index, so order
  is safe — but keep caller-nonce last for readability.) Update the package
  doc comment: the token now commits to the live TLS session's RFC 9266
  exporter, not just the cert — nothing binds a relay's separate session to
  this value.
- **AWS variant (`attestation_aws.go`):** fold `channelBinding` into the COSE
  document's layer-7 commitments the same way (extend the 64-byte UserData
  structure or add it alongside — mirror how leaf fp / device hash are
  committed there; keep it a distinct committed field). AWS isn't the audited
  live path, but the signature change forces it and it should bind analogously.

### 4. `enclave-go/cmd/enclave/http_io.go` + `main.go` — thread it at the handler

- `serveAttestation` gains a `channelBinding []byte` param, passed to
  `attestation.Get(leafDER, deviceBlob, nonce, channelBinding)`.
- At `main.go:357` (the `/attestation` dispatch), compute
  `exporter, err := <conn>.SelectedExporter()` (via the wrapper). On error
  (e.g. sub-1.3 connection): serve the token WITHOUT the binding (pass nil) so
  legacy 1.2 clients still get today's behavior — but this path is the reason
  to require 1.3 (see change 5). Pass `exporter` into `serveAttestation`.
  The handshake is already complete here (readRequest at :324 triggered it).

### 5. `enclave-go/internal/enclavetls/cert.go` — require TLS 1.3 on the attested listener

Bump the attested public listener `MinVersion` from `tls.VersionTLS12` to
`tls.VersionTLS13` (both sites: ~:154 and ~:221). Rationale in a comment: the
exporter channel binding (RFC 9266) is only sound on 1.3; every supported SDK
client and modern tool negotiates 1.3. **Flag this in the PR body as a
compatibility decision for Joseph to confirm at deploy.** (Leave the vsock
internal client config untouched.)

### 6. Reference verifier `tools/verify-attestation.py` — verify the binding E2E

Stdlib `ssl` CANNOT export keying material (confirmed absent even in 3.14), so
the verifier must use **pyOpenSSL ≥ 22.0** (`Connection.export_keying_material`)
for the attestation connection. Add pyOpenSSL to the tool's deps/inline
requirements. Update the live check to:
1. Open a pyOpenSSL TLS 1.3 connection to the gateway; complete the handshake.
2. `exporter = conn.export_keying_material(b"EXPORTER-Channel-Binding", 32)`.
3. Over the SAME connection, `GET /attestation`, read the JWT.
4. Existing checks: RS256 vs Google JWKS, `image_digest` vs pinned, served
   leaf cert SHA-256 ∈ `eat_nonce`.
5. NEW: assert `hex(exporter)` ∈ `eat_nonce` — the session binding. Fail loud
   if absent (that means either a pre-Tier-B enclave or a relay that couldn't
   bind your session).
Document at the top: the client MUST fetch `/attestation` and send its
sensitive requests over the SAME TLS connection (connection pinning) — the
binding covers one session; a new connection needs a fresh attestation. Keep
the existing multi-connection race test but assert each connection's OWN
exporter is bound in its OWN token.

## Tests (`enclave-go`, Go; name the layers)

Unit:
- `SelectedExporter` returns 32 bytes from a completed TLS 1.3 conn; errors on
  a non-TLS conn and on a (simulated) sub-1.3 `ConnectionState`.
- `attestation.Get` (GCP): with a non-nil `channelBinding`, the decoded token's
  `nonces` contains `hex(channelBinding)` AND still contains leafFP+deviceHash;
  with nil, it's absent and output equals today's (backward-compat).
- Server-derivation guard: the exporter nonce in the token is independent of
  the caller-supplied `nonce` — passing a caller nonce equal to some attacker
  value does not populate/relabel the exporter entry (the two are distinct
  committed slots). This is the anti-forgery property.
Functional:
- `serveAttestation` with a fake conn exposing a TLS 1.3 `ConnectionState` +
  a known exporter: the emitted token binds that exporter; with a sub-1.3
  conn, the token omits it and the handler still 200s (legacy path).

Use httptest / a minimal fake `*tls.Conn`-like as needed; if a real TLS 1.3
loopback is easier for the exporter test, stand one up in-test
(net.Pipe won't give an exporter — use a real `tls.Server`/`tls.Client` over
a `net.Conn` pair with a self-signed 1.3 config).
