# Task: G6 Tier B inc1 round 5 — reconciler backward-compat (unblock the rolling deploy)

Fix round on branch `g6-tierb-exporter-binding` (build on rounds 1-4; revert
nothing). The enclave deploy FAILED at the pre-rollout `Reconcile enclave DNS`
step: it runs the NEW verifier against the STILL-OLD fleet (no MIG roll yet),
and the new verifier hard-requires BOTH the exporter binding AND the same-socket
keep-alive pin — neither of which pre-Tier-B enclaves provide — so all instances
`[FAIL]`, "0 healthy", and the whole rollout aborts. Prod is unaffected (the
reconciler refused to shrink DNS). This is a deploy-ordering deadlock: the fleet
can't roll until reconcile passes, and reconcile can't pass until the fleet
rolls.

Root cause / correct model: the DNS reconciler's job is LIVENESS + image-digest
identity gating — a relay cannot forge a Google-signed token carrying an
accepted `image_digest`, so instance identity is proven by the digest
attestation. The RFC 9266 exporter binding is a CLIENT-session confidentiality
control, enforced at client connect (and by strict verification), NOT by the
reconciler's DNS decision. So the reconciler must verify what BOTH old and new
enclaves provide and treat the exporter binding + keep-alive pin as strict-only.

Do NOT commit. Do not touch `.codex-*` files.

## Change 1 — `tools/verify-attestation.py`: a backward-compatible liveness mode

Add `--no-require-exporter-binding` (default: exporter binding REQUIRED — all
current strict behavior is unchanged for client/security use). When set, the
verification is LIVENESS mode:
- STILL verify (against old AND new enclaves): valid Google-signed RS256 JWT vs
  JWKS; `image_digest` ∈ `--expect-digest` set; `dbgstat` not enabled; the
  served leaf-cert SHA-256 bound in `eat_nonce`; the fresh caller nonce present
  (anti-replay) — keep `require_gcp_fresh_exporter_binding`'s freshness checks
  (nonce present, ≥16 bytes) but make the EXPORTER-present requirement
  conditional on `require_exporter`.
- SKIP the same-socket pin follow-up: `fetch_attestation_same_tls_socket` must
  not fail when the server does not keep the connection alive. Add a
  `require_pin: bool` (or thread the mode) so that in liveness mode it performs
  a SINGLE `/attestation` fetch and does NOT send/require the second
  same-socket request. In strict mode (default) it keeps the round-3 pin
  demonstration exactly as-is.
- Multi-sample tolerance: if `--samples > 1` in liveness mode and the server
  sent `Connection: close` (old enclave), RECONNECT for each sample instead of
  erroring, so `--samples 2` works against a non-keep-alive server. (In strict
  mode, same-socket keep-alive is required and unchanged.)
- If the exporter binding IS present in liveness mode, you may still verify it
  matches (bonus), but its ABSENCE must not fail.

Thread the resolved `require_exporter` boolean from `main()` (the new flag) into

MinVersion is 1.2, so the handshake still negotiates 1.3).

Update the module docstring: `--no-require-exporter-binding` = liveness/identity
