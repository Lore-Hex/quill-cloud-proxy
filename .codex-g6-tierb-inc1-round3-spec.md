# Task: G6 Tier B inc1 round 3 — connection pinning (keep-alive so attestation + prompt share one TLS session)

Fix round on branch `g6-tierb-exporter-binding` (build on the uncommitted
rounds 1-2; revert nothing). This closes the last blocker (codex P1 / Fable
should-fix): the RFC 9266 exporter binds ONE TLS session, but `/attestation`
sends `Connection: close` and the serve loop is one-request-per-connection, so
the client is forced to send its prompt on a DIFFERENT connection whose exporter
was never attested — the operator relays that prompt connection freely. The fix
lets the SAME TLS session carry `/attestation` and then the prompt, so a client
can pin.

This touches the core serve loop that handles ALL production traffic. Keep the
change MINIMAL and preserve byte-identical behavior for the non-attestation
path. Do NOT commit. Do not touch `.codex-*` files. `enclave-go/`.

## Design — "attest-then-request" keep-alive (minimal, low-risk)

The ONLY new capability: after a successful `GET /attestation`, the connection
stays open so the client can send its next request (the prompt) on the SAME TLS
session. Every non-`/attestation` response keeps its existing framing and STILL
closes the connection (return) — so real inference requests, streaming, and the
health path are byte-identical to today. A connection therefore serves
zero-or-more `/attestation` requests followed by exactly one real request, then
closes.

### 1. `cmd/enclave/http_io.go` — persistent reader

`readRequest` currently does `bufio.NewReader(r)` per call, which buffers ahead
and would lose bytes between requests on a kept-alive connection. Refactor:
`readRequest(br *bufio.Reader) (...)` takes a reader owned by the caller. The
serve loop creates ONE `bufio.NewReader(conn)` per connection and reuses it for
every request. (A `GET /attestation` has no body, so after reading it the reader
is positioned exactly at the next request — no smuggling window. Preserve the
existing Content-Length parsing exactly.)

### 2. `cmd/enclave/http_io.go` — `/attestation` response is keep-alive

`serveAttestation` currently writes `Connection: close`. Change ONLY the
`/attestation` success response to `Connection: keep-alive` (it already sends a
correct `Content-Length`, so the client can find the end and reuse the socket).
Error responses from `/attestation` (503/500) keep `Connection: close`. Every
other response writer is UNCHANGED (still `Connection: close`).

### 3. `cmd/enclave/main.go` — the serve loop

Restructure `serveOne` so the request dispatch runs in a bounded loop over the
persistent reader:
- Before each read, set a fresh idle read deadline (reuse the existing 30s
  handshake/read-deadline value) so a client that attests and never sends the
  next request cannot pin the goroutine; clear it after the request is read
  (as today) so streamed responses aren't truncated.
- Read a request. On read error / EOF → close (return).
- If it's `GET /attestation`: serve it (fail-closed exporter logic from round 2,
  keep-alive framing), increment an attestation counter, and if the counter is
  under a small cap (e.g. `maxAttestationsPerConn = 8`, to bound an attest-loop
  DoS) `continue` the loop to read the next request; at the cap, close.
- For ANY other route (or an `/attestation` that failed): serve exactly as
  today and `return` (close). This preserves one-shot semantics + all existing
  framing for real traffic.
Keep the per-request logging/stats behavior intact for each iteration (the
request_accept/request_end log pair should still bracket each served request;
adapt the existing deferred logging so it reports per-request, or log per
iteration — do not lose the existing observability).

Preserve: the `responseStatsConn` wrapper, the `SetReadDeadline` semantics for
the handshake-deferral comment (main.go:292), and the bearer/route handling.

### 4. Reference verifier — DEMONSTRATE the pin

`tools/verify-attestation.py`: in the live same-socket flow
(`fetch_attestation_same_tls_socket` and its `--samples` caller), after
fetching `/attestation` and verifying the exporter+fresh-nonce binding on the
socket, send a SECOND request over the SAME pyOpenSSL socket (a second
`GET /attestation` with a NEW fresh nonce is simplest and needs no auth) and
assert: (a) it is served (the connection stayed open — proves keep-alive), and
(b) its exporter binding equals the first (SAME session — proves the pin
carries across requests). Fail loudly if the socket was closed after the first
response (that would mean pinning is impossible and the binding is cosmetic).
Update the module docstring: pinning is now enforced/available at the server;
clients MUST send sensitive requests on the attested socket, demonstrated here.
